# AI Brand Content Agent (C#)

Консольный AI-агент для подготовки публикаций кофейни NORTH Coffee.

## Что умеет программа

1. Принимает запрос, например: `Подготовь пост про осенние напитки`.
2. Через **Groq Tool Calling** сам решает вызвать `list_available_photos` и получает список фотографий с описаниями и тегами.
3. Выбирает подходящую фотографию и готовит текст поста, заголовок, подзаголовок и 3–5 хештегов.
4. Вызывает `render_brand_image`: C# + SkiaSharp обрезают фото до квадрата 1080×1080, помещают логотип и накладывают заголовок.
5. Вызывает `save_draft`: приложение проверяет данные и сохраняет черновик в JSON.

Это именно цикл tool calling: приложение передаёт модели описания функций, получает от модели `tool_calls`, запускает запрошенные функции и отправляет результаты обратно в Groq. Вызовы инструментов не прописаны как безусловная последовательность в коде — решение о вызове принимает модель.

## Требования

- .NET 10 SDK.
- Ключ Groq API.
- Доступ в интернет для обращения к Groq и загрузки NuGet-пакетов при первом запуске.
- Исходные фотографии JPG/PNG.

## Как устроен проект

```text
Agent/ContentAgent.cs             — цикл AI-агента и tool calling
Tools/AgentTools.cs               — локальные инструменты агента
Services/GroqApiClient.cs         — HTTP-клиент Groq API
Services/PhotoCatalog.cs          — каталог и проверка исходных фотографий
Services/BrandImageRenderer.cs    — оформление картинки через SkiaSharp
Models/                            — модели данных
config/                            — бренд и рубрики
assets/photos/                     — исходные фото и метаданные
assets/logo.png                    — логотип

drafts/                            — JSON-черновики
drafts/images/                     — готовые изображения
```

## Что важно понимать про Tool Calling

- Модель видит схемы трёх инструментов: `list_available_photos`, `render_brand_image`, `save_draft`.
- Модель формирует название инструмента и JSON-аргументы.
- Программа исполняет именно запрошенный инструмент, возвращает его результат модели и продолжает диалог.
- Инструменты работают локально: фотографии не отправляются в сервис обработки изображений. В Groq отправляются текст запроса, правила бренда и метаданные фотографий.
- Перед сохранением программа отдельно проверяет, что фото существует, а `photo_id` и `image_path` совпадают с результатом реально созданной картинки.

## Установка и запуск

Открой терминал в папке проекта.

### 1. Настрой API-ключ

Скопируй `.env.example` в `.env` и вставь свой ключ:

```env
GROQ_API_KEY=gsk_твой_ключ
GROQ_MODEL=openai/gpt-oss-120b
```

Не отправляй `.env` в Git и никому не показывай API-ключ.

### 2. Добавь фотографии

Положи фотографии в `assets/photos/`, например:

```text
assets/photos/
├── photos.json
├── autumn_latte.jpg
├── cappuccino.jpg
└── coffee_beans.png
```

Открой `assets/photos/photos.json` и добавь для каждого файла описание. Пример одной записи:

```json
{
  "id": "photo_001",
  "file": "autumn_latte.jpg",
  "description": "Капучино с корицей на деревянном столе, тёплый осенний свет",
  "category": "Напитки",
  "tags": ["капучино", "корица", "осень", "кофе"]
}
```

ID должны быть уникальными. Имя файла должно точно совпадать с реальным именем файла в `assets/photos/`. Примерная запись уже есть в `photos.json`, но её `file` нужно заменить на существующую фотографию.

### 3. Замени логотип

Замени `assets/logo.png` логотипом своей кофейни. Желательно использовать PNG с прозрачным фоном. Путь к логотипу задаётся в `config/brand.json` в поле `logoPath`.

### 4. Запусти

```bash
dotnet restore
dotnet run
```

Введи запрос в консоли. Например:

```text
Подготовь пост про осенние напитки
```

Для выхода введи `выход`.

## Где искать результат

После успешной работы появятся два файла:

- `drafts/ГОДМЕСЯЦДЕНЬ_ВРЕМЯ_тема.json` — текст, хештеги, ID фото, заголовки и путь к картинке.
- `drafts/images/post_ГОДМЕСЯЦДЕНЬ_ВРЕМЯ_....png` — готовое изображение 1080×1080.

## Настройка фирменного стиля

Основные настройки бренда лежат в `config/brand.json`:

- `description` — описание бизнеса;
- `toneOfVoice` — Tone of Voice;
- `styleRules` — правила написания;
- `forbiddenPhrases` — нежелательные фразы;
- `fontFamily` — системное семейство шрифтов;
- `logoPath` — путь к логотипу.

Рубрики и примеры тем лежат в `config/topics.json`.

Если нужен фирменный шрифт, установи его в операционной системе и укажи его семейство в `fontFamily`. Код использует установленный шрифт; файл шрифта в проект не включён.

## Ограничения первой версии

- Это консольный MVP: публикация в соцсети, расписание, база данных, веб-интерфейс и деплой не реализованы.
- Модель выбирает фото по текстовым описаниям и тегам, а не анализирует пиксели фотографий.
- Макет пока один: квадрат 1080×1080, логотип сверху слева, текст снизу. Координаты и цвета можно менять в `Services/BrandImageRenderer.cs`.
- Для кириллицы желательно использовать системный шрифт с поддержкой русского языка, например Arial.
