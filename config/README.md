# Настройка бренда и тем публикаций

В этой папке находятся два JSON-файла, которые управляют содержанием публикаций:

* `brand.json` — информация о компании и правила фирменного стиля.
* `topics.json` — рубрики и примеры тем, на которые агент может ориентироваться.

Оба файла должны оставаться корректными JSON. Используй двойные кавычки вокруг названий полей и строк, не ставь запятую после последнего элемента массива или объекта.

## 1\. `brand.json` — профиль бренда

Пример:

```json
{
  "brandName": "NORTH Coffee",
  "description": "Городская кофейня с авторскими напитками и свежей выпечкой.",
  "toneOfVoice": "Дружелюбный, тёплый и современный. Общаемся как бариста с постоянным гостем.",
  "styleRules": \[
    "Пиши простым языком, без канцелярита.",
    "Используй короткие абзацы.",
    "Не используй больше двух эмодзи в одной публикации.",
    "Не дави на покупателя и не используй агрессивные призывы к покупке."
  ],
  "forbiddenPhrases": \[
    "лучший кофе в мире",
    "самые низкие цены",
    "успей купить прямо сейчас"
  ],
  "fontFamily": "Arial",
  "logoPath": "assets/logo.png"
}
```

Описание полей:

|Поле|Что указывать|
|-|-|
|`brandName`|Название компании или проекта. Используется в контексте агента и приветствии.|
|`description`|Чем занимается бизнес, какие товары или услуги предлагает, чем отличается. Добавь важные особенности и целевую аудиторию.|
|`toneOfVoice`|Как бренд должен звучать: дружелюбно, экспертно, с юмором, сдержанно и т. п. Можно описать, как бренд обращается к аудитории.|
|`styleRules`|Массив конкретных правил написания. Каждый элемент — отдельная строка-инструкция.|
|`forbiddenPhrases`|Массив фраз и формулировок, которые нельзя использовать. При необходимости добавь нежелательные обещания или рекламные клише.|
|`fontFamily`|Название шрифта, установленного в операционной системе, например `Arial`. Для кириллицы выбери шрифт с поддержкой русского языка.|
|`logoPath`|Путь к логотипу относительно корневой папки приложения. Например, `assets/logo.png`. Предпочтителен PNG с прозрачным фоном.|

## 2\. `topics.json` — рубрики и темы

Пример:

```json
{
  "categories": \[
    "Напитки",
    "Кофейная культура",
    "Атмосфера кофейни",
    "Сезонные предложения",
    "Выпечка и десерты",
    "Знакомство с командой"
  ],
  "exampleTopics": \[
    "Осенние напитки",
    "Как выбрать зерно для фильтр-кофе",
    "Идеальный кофе в дождливый день",
    "Свежая выпечка к утреннему капучино"
  ]
}
```

Описание полей:

|Поле|Что указывать|
|-|-|
|`categories`|Основные рубрики контента. Например: новости, продукты, советы, команда, отзывы, акции, закулисье.|
|`exampleTopics`|Конкретные идеи публикаций внутри рубрик. Добавь темы, которые подходят бренду и его аудитории.|

Можно добавлять и удалять элементы массивов. Если пока нет готовых идей, допустимо оставить пустой массив `\[]`. Не добавляй поля с другими именами: приложение ожидает именно `categories` и `exampleTopics`.

## 3\. Где хранить логотип и фотографии

Логотип, указанный в `logoPath`, должен существовать по этому пути. Для стандартной структуры проекта используй `assets/logo.png`.

Исходные фотографии и их описания находятся в `assets/photos/` и `assets/photos/photos.json`. Инструкция по добавлению фотографий находится в `assets/photos/README.txt`.

## 4\. Проверка JSON

Перед запуском проверь, что:

* файлы сохранены в кодировке UTF-8;
* все ключи и строковые значения заключены в двойные кавычки;
* массивы и объекты закрыты скобками;
* в конце последнего элемента нет лишней запятой;
* пути к логотипу и фотографиям соответствуют реальным файлам.

Если JSON содержит синтаксическую ошибку, приложение не сможет загрузить настройки.
